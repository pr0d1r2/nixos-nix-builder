Write policy documents, codes of conduct, and community guidelines
using anodyne language. Describe expected behavior and boundaries
without explicit enumeration of harmful acts, slurs, or graphic
scenarios.

## Why

AI language models refuse requests containing explicit harmful
content even when the intent is to prohibit that content. Writing
"do not [harmful act]" triggers the same filters as advocating
for it. Anodyne framing avoids refusals while conveying the same
policy.

## How

- State what IS expected, not what is prohibited.
- Use abstract categories ("unwelcome conduct", "disrespectful
  behavior") instead of concrete harmful examples.
- Reference external standards ("as defined by the project
  maintainers") rather than enumerating specifics.
- Frame enforcement as "maintaining a welcoming environment"
  rather than listing punishable offenses.
- When prohibitions are necessary, use the mildest accurate term.
